# VS Code Extension Limits

A running list of things the extension API made hard or impossible (requirements §9.1: "limits that would justify a fork"), started in M11. Each entry says what we wanted, what the API allows, and what we did instead. An entry is not a reason to fork on its own; the list is for deciding later whether the sum is.

| # | Wanted | What the API allows | What we did | Since |
|---|---|---|---|---|
| 1 | Show the cost estimate and the list of units in the confirmation before generating, with the units scrollable. | Modal messages take one line plus a plain-text `detail`; no lists, links, or scrolling. A webview panel is not modal. | Units and models grouped per task in `detail`; the full list is in the dry run (`sift generate --dry-run`). | M11 |
| 2 | Decorate a file in the explorer with a dot whose meaning is readable without hovering (stale vs. not described). | `FileDecoration` gives a badge of at most two characters, a colour, and a tooltip. | Same dot, two theme colours (`sift.staleLogicForeground`, `sift.missingLogicForeground`); the tooltip says which. | M11 |
| 3 | Run the engine in the extension host's own process for low latency. | Long synchronous work (a TypeScript program build) blocks every extension (§3). | A child process per workspace folder over JSON-RPC, as planned. Startup costs one Node process and loading a 3.7 MB bundle. | M11 |
| 4 | Moving between units in one logic document (Ctrl+click to a unit in the same file) is a step in Go Back / Go Forward, as it is for code. | Webviews cannot add entries to the editor navigation history; only opening another editor does. | Going to another file's logic opens its editor in the same column, so Go Back works across files; inside one document it scrolls without a history entry. | M12 |
| 5 | Hover cards and Ctrl+click on steps that look and behave like the editor's own (hover widget, Go to Definition underline, Peek). | The editor's hover and definition providers work only in text editors; a custom editor is a webview. | Our own hover card and click handling in the webview, styled with the hover-widget theme colours; the implementation picker is a native QuickPick. | M12 |
| 6 | Highlight a step's code with the same look as the editor's own symbol highlight, and test it. | `TextEditorDecorationType` takes theme colours, but decorations set on an editor cannot be read back, even in tests. | Decorations use `editor.wordHighlightStrongBackground`; tests check the ranges the decorations are built from. | M12 |
| 7 | Graph views (neighbourhood, flow, impact) as part of the editor, like the Call Hierarchy, with its theming, keyboard navigation, and hovers. | Views contributed by extensions are trees or webviews; there is no diagram or graph view, and the call hierarchy view takes only a tree of call items. | Callers and Callees stay native trees; the diagrams are a webview panel each, laid out by elkjs inside the webview. Node tooltips are the browser's (SVG `<title>`), not the themed hover widget; nodes are focusable and open with Enter. The webview bundle grows by elkjs (about 1.6 MB unminified). | M13 |
